# 可回收火箭归零闭环

记录可回收火箭异常调查、改进验证和构型放行。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块统一加载这些资料，并校验领域标识、版本、参与方、事实和约束等必要字段。

当前资料反映以下领域事实：

- 航天归零包括收集数据、故障树排查、复现、机理分析和措施验证
- 朱雀三号首次回收尝试在着陆点火后异常坠落
- 后续任务实现我国首次火箭陆地回收

## 归零闭环记录

`contracts/closure.schema.json` 描述闭环记录结构，`fixtures/closure.json` 给出 Y1 回收异常调查的完整样例，`src/closure.py` 负责加载、校验并派生放行结论与准备会视图。

闭环记录覆盖：遥测片段、飞行构型、软件版本、环境、故障树嫌疑项、复现实验、改进措施、多专业结论、后续记录、独立审查和构型放行。

### 调查规则

- 每个嫌疑项必须写明支持或排除证据；标记"已排除"需有排除证据，标记"已关闭"需有支持证据
- 嫌疑项关闭前，关联措施须完成地面验证并通过独立审查；已拆分的措施由子措施承接验证责任
- 多专业并行调查允许结论冲突；两个及以上专业共享的结论必须已确认
- 数据重解码、试验失败、措施拆分、供应商反馈均须形成后续记录
- 独立审查人不得与措施负责人为同一人
- 未关闭的高风险嫌疑项阻止相关构型放行，放行记录必须与门禁一致

### 准备会视图

`readiness_board` 给出下一发准备会视图：尚未证实的假设、已在地面验证的措施、仍需飞行验证的部分及各自责任人，以及放行门禁结论。

```python
from pathlib import Path
from src.closure import load_closure, readiness_board

data = load_closure(Path("fixtures/closure.json"))
board = readiness_board(data, "CFG-B2")
```

### 飞行结果更新

`apply_flight_result` 在飞行结果回来后更新状态：回收成功则待飞行验证的措施记为飞行验证通过；回收失败则相关嫌疑项重新打开，原放行结论作废并会被校验标出。两种情况都追加飞行结果后续记录，原记录不被改动。
