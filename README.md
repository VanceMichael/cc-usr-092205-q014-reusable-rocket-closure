# 可回收火箭归零闭环

记录可回收火箭异常调查、改进验证和构型放行。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块统一加载这些资料，除校验领域标识、版本、参与方、事实和约束等必要字段外，还强制闭环规则：嫌疑项必须挂证据、结论确认须独立审查人签署、措施负责人与审查人分权、未关闭高风险项阻止构型放行、准备会视图与底层状态一致。

当前资料反映以下领域事实：

- 航天归零包括收集数据、故障树排查、复现、机理分析和措施验证
- 朱雀三号首次回收尝试在着陆点火后异常坠落
- 后续任务实现我国首次火箭陆地回收
- 技术归零要求定位准确、机理清楚、问题复现、措施有效、举一反三
- 入轨目标完成不等于回收闭环完成，未归零前不得把下一发成功当作答案

## 闭环结构

样例以一次着陆点火后异常为起点，覆盖：

- 遥测片段、飞行构型（含软件版本与硬件序列号）和环境条件，作为调查输入
- 故障树嫌疑项，每项写明支持或排除证据；多专业并行调查可记录冲突观点，但结论只有经独立审查人签署才能确认为共享结论，未确认前只能作为假设出现在准备会视图上
- 复现实验与改进措施；数据重新解码、试验失败、措施拆分和供应商反馈只追加后续记录，不改写原始记录
- 措施负责人与独立审查人分权；未关闭的高风险项阻止相关构型放行，放行门槛由故障树状态推导，不允许手工跳过
- 准备会视图按状态汇总：尚未证实的假设、已在地面验证的措施、仍需飞行验证的措施，各带责任人
- 飞行结果回来后形成飞行回顾，逐条更新假设与措施状态，放行门槛随之重新计算

`DOC-` 前缀的证据来源编号表示案头记录（如残骸检查、软件版本比对），其余来源必须能追溯到遥测、实验、环境或后续记录编号。

## 本地校验

运行项目自带测试可确认样例资料符合约定。仓库不保存账号、密钥、连接串或真实身份资料。
